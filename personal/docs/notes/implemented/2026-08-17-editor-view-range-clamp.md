# Agent Note: str_replace_editor 的 view 把越界终行截回末行

Status: implemented

## 问题

`view` 命令会拒绝任何终行超过文件行数的 `view_range`：对一个 48 行的文件传 `view_range=[1, 200]`，整个调用就失败。模型习惯拿一个够大的上界表示"文件剩下的部分"，于是一次本来读一遍就能答的请求，要先赔上一次失败的工具往返再重试。真实记录里用户反复看到 `Invalid view_range`。

## 决策

`formatFileView` 把越界的终行截回文件末行，按截断后的区间作答，并在提示里回显实际生效的区间。其余无效输入照旧报错：参数个数不对、不是整数、起始行不在 `[1, 行数]` 内、终行小于起始行（`-1` 仍然表示"读到末尾"）。

## 备选方案

**保留报错，让模型重试。** 否决：报错信息里说的那个行数，正是成功时本来就会展示的内容，重试一次拿到的也就是截断后的结果——白白多走一轮。

**起始行也一起截。** 否决：越界的起始行选不出任何内容，截它等于替调用方编了一个他没有指定的区间；在这里直接失败，工具的行为才如实。

## 后果

- 用大上界"读剩余部分"的 view 第一次调用就成功，并报出实际生效的区间，模型从同一份输出就知道了文件的真实长度。
- 工具的测试断言了这个截断行为，其余错误路径继续全覆盖；逐文件覆盖率保持在仓库要求的 100%。
