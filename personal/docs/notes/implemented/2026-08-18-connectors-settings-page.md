# Agent Note: 连接器设置页

Status: implemented

新包 `packages/client/ui-settings-connectors/`：设置里多一个"连接器"导航项，列出所有能从外面接进 dsh 的应用渠道，自带飞书那一张卡片，并把 `settings.connector.item` 作为下一个渠道自己挂卡片的位置。同一轮还调了设计模式和写作模式的视觉。

## 问题

飞书通道（`personal/plugins/dsh-x-feishu/`）已经能跑，但它的五个配置项——用哪个预设、卡片密度、刷新间隔、审批等待上限、桥接端点——只能手改 `$DSH_HOME/settings.yaml`。而且更麻烦的是反过来的情况：**没装的时候，界面里根本没有任何地方提到飞书**，用户不会知道有这条路，也不知道怎么开。

现成的"插件"页解决不了。它的卡片在命名空间不可用时直接不渲染，这在那边是对的——一个从没挂过 shell 执行器的部署不该露出它的限额。但连接器恰恰相反：**最该打开这一页的时刻，就是东西还没装的时候**。

## 决策

**独立的一级导航项，不做插件页下面的标签。** 连接器不是 agent 循环上的旋钮，它是外面进来的一条路，通常还要用户自己起一个常驻进程。放在插件页里，它会淹没在"bash 超时""web 搜索密钥"中间。order 取 18，夹在插件（15）和 Model Hub（20）之间。

**没装也列出来，但不给控件。** 没装的卡片显示渠道名、"未安装"角标、以及装它的那一行命令。不给控件是因为没有命名空间可写，摆一排禁用输入框只会引人去试。

**扩展点是 `settings.connector.item`。** 第二个渠道（钉钉、企业微信、Slack）自己一个包，注册一条进来就行，不用改这个包。卡片外壳、两种控件、暂存表单都留在包内部——客户端打包门禁不允许跨包 import 这些值，所以想要同一套外壳的渠道应该把卡片注册到这里。

**表单模型自己写了一份，没复用 `ui-settings-plugins` 的 `CardForm`。** 不是不想复用，是不能：客户端打包纯度门禁禁止跨插件包的值 import，服务和 slot 才是合法通道，而表单模型两样都不是。抄过来的这份少了写-only 凭证控件——连接器的凭证从不放在设置文档里，飞书的密钥在 `lark-cli` 后面的系统 keychain 里，由桥接进程持有。

## 代价

- **导航行是通用齿轮图标。** `ui-settings-general` 的 `navIcon(id)` 把 section id 映射到图标，那是上游文件，本 fork 不改，所以 `connectors` 落到兜底分支。
- **角标只说装没装，不说活没活。** socket 连没连上、桥接起没起，这一页看不到。要报这个得让渠道插件提供一个状态接口，目前一个都没有。
- **桥接自己的 `config.json` 够不着。** 名单、事件配置目录、机器人 open id 都在那里，不在设置命名空间里。

## 视觉

设计模式（`ui-ued`）改动大一些：

- **加了预览宽度切换**（自适应 / 桌面 1280 / 平板 768 / 手机 390）。原型是照着某个视口写的，而舞台的宽度是"减掉左边栏和同伴面板之后剩下的"，想在指定宽度下看一眼，原来只能去拽窗口。
- 左栏表头改成 42px 并 sticky，跟右边舞台表头对齐在同一条基线上；长列表滚动时刷新按钮不再被卷走。
- 选中行加了一条 2px 竖条。原来只有配色，而 hover 用的是同一个填充色，鼠标一走就分不清哪个是当前预览的。
- 目录和原型混在一个列表里，靠图标配色分开（跟写作模式的文件树同一套）。
- 舞台底色下沉一层，iframe 加了 `--dsw-shadow-lv2`——原型多半是白底页面，不这样它会跟面板糊在一起。

写作模式（`ui-writing`）是小修：当前文档行加同样的竖条、字数统计用等宽数字（原来每敲一个字整行都在抖）、选中高亮换成品牌色调、空状态限宽并统一行高。

## 顺手挖出来的三件

这一轮为了刷新 web 快照，跑了一次久违的全量 web e2e，翻出三件先前就红着的东西。

**一、`ui-ued` 整个包一行覆盖率都没有。** 视图、客户端入口、locales、invariant 全是 0——只有 `sandbox.client.spec.ts` 一个测试文件，它只 import 了 `sandbox.ts`。逐文件 100% 的门禁在这个包上一直是红的，是我交 C 阶段时留下的洞。已补齐到 100%（35 条），包括视图的列目录 / 进出目录 / 选中渲染 / 迟到回复丢弃 / 去抖重绘 / 宽度切换，以及 apply 的预设门、documents 回调、按会话分发。

**二、「写作」和「设计」两个标签页出现在每一个会话上。** `conversation.view` 的注册是全局的，`declarePreferredView` 只决定**默认打开**哪个视图，藏不掉标签。28 份快照因此陈旧了很久——写作模式落地起就没再跑过全量 web 套件。`ui-ued` 的 README 原来写"没有这道门，任何会话只要工作区里有 HTML 就会拿到一个渲染入口"，这句话过头了：自动那条路确实被挡住了，但人手动点「设计」照样能渲染那个工作区的 HTML。README 已改成如实说明，并记进已知限制。要真按会话隐藏，得在 `ctx.conversation` 上加一个可用性 resolver，那是上游包。

**三、`模型` 和 `模型中心` 两个导航项撞了。** Playwright 的 `getByRole(name)` 不加 `exact` 是子串匹配，所以 `{ name: '模型' }` 同时命中两个按钮，strict mode 直接报错；对话框留在打开状态，它的遮罩挡住后面每一次点击，于是同文件剩下的用例全部 30 秒超时。四个文件八处定位器，19 条失败一个根因。这是 `feat(model-hub): register in web bundle` 引入的，同样因为没人再跑全量套件而没被发现。修法是给这八处加 `exact: true`——同一个文件里 `'插件', exact: true` 本来就是这么写的。改的是上游文件，代价是多一处极小的合并面。

## 验收

新包 48 条测试，逐文件覆盖率 100%。`test:gui` 288 个文件全绿。静态门禁重新生成了 client / config / module-graph 三份目录。
