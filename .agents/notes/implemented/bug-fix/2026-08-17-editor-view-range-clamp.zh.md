# Agent Note: str_replace_editor 的 view 收敛越界终行

Status: implemented

[English](2026-08-17-editor-view-range-clamp.md) | 中文

## Problem

`view` 命令拒绝任何终行超过文件行数的 `view_range`——对 48 行文件传 `view_range=[1, 200]` 会让整个调用失败。模型常用填充上界表示"文件的剩余部分"，于是会话为一次文件本可直接回答的请求付出一次失败的工具往返和重试；用户在真实记录里反复看到 `Invalid view_range` 报错。

## Decision

`formatFileView` 把越界终行收敛到文件末行，以截断后的区间作答，并在提示中回显实际生效（收敛后）的值。仍然无效的输入依旧报错：参数个数错误、非整数、起始行超出 `[1, 行数]`、终行小于起始行（`-1` 仍表示"到末尾"）。

## Alternatives considered

**保留报错让模型重试。** 否决：报错信息复述的行数正是成功答案本会展示的内容，重试一次后得到的就是收敛结果——白白多一轮。

**连起始行也收敛。** 否决：越界起始行选不出任何内容，收敛它等于发明调用方没有指定的区间；在此处失败保持契约诚实。

## Consequences

- 填充式"读剩余部分"的 view 首次调用即成功并报告生效区间，模型从同一份输出获知文件的真实长度。
- 工具的测试断言收敛行为并继续覆盖其余全部错误路径；按文件覆盖率保持在仓库的 100% 门禁。
